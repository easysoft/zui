# ZUI Helper 规范

## 分类

先确定 helper 的所有权和行为类型：

| 类型 | 设计重点 |
| --- | --- |
| 库内私有 helper | 与单一实现紧耦合，不从库入口公开 |
| 纯函数、常量或类型 | 确定性、无副作用、完整输入/输出类型 |
| 状态类 | 实例所有权、重入、并发、reset/destroy |
| store 或单例 | 状态域、持久化、订阅、序列化、版本与清理 |
| 浏览器 DOM 模块 | DOM 生命周期、事件/observer/计时器清理、环境防护 |

不要因为可能复用就把私有 helper 放入 `@zui/helpers`。先检查使用方、稳定性和发布承诺。通用纯函数通常适合 `js-lib`；浏览器、DOM 或持久化集成通常适合 `js-helpers`，但最终以现有构建语义和相似库为准。

## 纯函数和类型

- 默认无副作用、确定性，不读取或写入隐式全局状态。
- 明确定义空值、非法输入、边界数值、locale/timezone（若相关）和错误语义。
- 不用宽泛 `any` 掩盖不确定性；使用泛型、联合或 type guard 表达约束。
- 不为便利偷偷改变传入对象，除非 API 名称、类型和文档明确承诺可变行为。
- 可组合的小函数优于同时处理多个无关领域的大型 helper。

## 状态、store 与浏览器模块

明确：

- 谁创建和持有实例，是否为单例；
- 初始状态、更新入口、订阅顺序和重复调用行为；
- 序列化格式、不可序列化值、版本兼容和损坏数据处理；
- local/session/memory 等后端的选择和失败回退；
- 异步竞态、取消、错误传播和恢复；
- 监听器、observer、timer、缓存和 DOM 引用的销毁；
- `window`、`document`、storage 等全局对象不可用时的行为。

单例必须避免导入时产生不必要副作用。需要副作用时，让入口与生命周期显式可见。

## 公开 API

- 对公共函数、类、options、事件和非直观错误行为添加必要 JSDoc。
- 从最近的局部 `index.ts` 和库 `src/main.ts` 显式导出。
- 不让消费者依赖未承诺的深层路径；若仓库现状已有深层导入，先判断是否属于兼容约束。
- 公开 API 使用稳定命名和返回类型；定义 Promise、iterator、unsubscribe 或 disposer 的行为。
- package `dependencies` 和 `zui.contributes` 与真实导出一致。

## 计划与验收

实施前计划必须包含分类、放置位置、公开 API、数据流/状态、副作用与清理、文件/导出/依赖、文档/调试需求及验收场景。尚无适用的明确批准时不编辑；批准复用与增量范围确认遵循 [共享工作流](workflow.md)。

验证至少覆盖：

- 正常、空值、边界和非法输入；
- 重复调用、并发或重入；
- 序列化/反序列化和损坏数据（若适用）；
- 浏览器 API 不可用、监听释放和 destroy（若适用）；
- 公共导出与类型解析；
- 目标库构建和针对性可执行检查。

仓库没有通用测试套件时，可以运行短小的只读/临时验证脚本，但不要把一次性测试产物留在仓库。
