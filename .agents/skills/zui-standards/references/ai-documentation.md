## 目的与文件

`lib/<name>/ai.md` 是面向使用者的单库参考；根目录 `ai.md` 是自动生成的检索入口。两者纳入 Git。开发流程和 Agent 行为继续由 `AGENTS.md` 与技能约束；AI 参考不覆盖这些规则。

本规范适用于所有内置库，包括 CSS、helper、基础设施和配置库。以当前源码为目标，不自动承诺已发布版本相同。已有官网文档保持原有结构；AI 参考使用普通 Markdown，不依赖官网组件或预处理。

从 [模板](../templates/ai.md) 创建文档；复制后替换标识与占位内容。代表参考：[Button](../../../../lib/button/ai.md)、[Menu](../../../../lib/menu/ai.md)、[Pager](../../../../lib/pager/ai.md)、[EventBus](../../../../lib/event-bus/ai.md)、[Utilities](../../../../lib/utilities/ai.md)。

## 文件结构

UTF-8、LF 换行，末尾保留一个换行。一级标题只有一个，使用库的展示名称。以下二级标题全部保留且顺序固定，不附加中文后缀：

| 标题 | 内容 |
| --- | --- |
| `meta` | 唯一 JSON 元信息块 |
| `overview` | 功能、场景、选型边界、相关库 |
| `setup` | 消费环境、真实入口、样式/资源依赖、注册步骤 |
| `vanilla` | 公开的原生 JS 组件 |
| `preact` | 公开的 Preact 组件 |
| `web-components` | 公开的自定义元素及元素 API |
| `css` | CSS 类或有界类族 |
| `css-variables` | 对外可配置 CSS 变量 |
| `javascript` | 工具函数、工具类、对象、常量、模块与配置导出 |
| `types` | 使用 API 所需的公开类型 |
| `recipes` | 常见任务的组合示例 |
| `constraints` | 限制、环境、易错点 |
| `references` | 正式文档、入口、类型与实现来源 |

确认没有对应能力时写 `无。`；未核实不能写“无”，写 `待核实：原因`，校验会报告文档未完成。未知、未接入或内部实现不能冒充可用 API。

`meta` 的第一个内容块必须是 `json` 围栏，结构为：

```json
{
  "schemaVersion": 1,
  "library": "menu",
  "summary": "提供菜单和多级列表的展示与交互能力。",
  "keywords": ["菜单", "多级菜单", "menu"]
}
```

`library` 必须与目录名一致；`summary` 是用于全局索引的一句话摘要；`keywords` 是非空字符串数组，涵盖中文场景和常用英文术语。包名、版本、库类型、WIP 等状态从 package.json 读取，不在元信息中重复维护。结构不兼容修改须提升 `schemaVersion`，不能改变 v1 含义。

## 条目与提取

三级标题只用于可提取条目，ID 满足 `^[a-z][a-z0-9]*(?:-[a-z0-9]+)*$`，在文件内唯一，且不能与二级标题重复。例如 `vanilla-menu`、`preact-menu`、`css-btn`。ID 与展示名称分开，文案修改不改变 ID。普通说明使用段落或四级标题，不占用三级标题。

条目标题后第一个内容块为 `json` 围栏：

```json
{
  "name": "Menu",
  "summary": "创建和管理菜单组件。",
  "keywords": ["菜单", "嵌套菜单"]
}
```

`name` 和 `summary` 必填且非空，`keywords` 可省略。`name` 使用真实 API 名称；多个同类能力归组时可用描述性名称，但正文须列出确切成员。CSS 条目额外包含 `role`，见下节。

条目正文以四级标题组织入口、签名、参数、事件、示例和来源。继承或共享 API 可链接到本文件或其他库的明确条目，并说明覆盖和不支持的部分；不能用一个“见源码”代替参数契约。类型可使用完整 TypeScript 定义代替重复字段表。

所有引用使用相对路径，不含本机绝对路径和易失效的源码行号。AI 文档链接指向稳定二/三级标题 ID。代码围栏内的标题不是文档结构；引用块与列表内的标题不作为顶层章节。使用四个反引号展示包含三个反引号的 Markdown。

脚本只结构化读取元信息，按源行号提取章节/条目 Markdown，不承诺把参数表解析成另一套 JSON API。提取不展开共享链接，不执行文档中的代码。

## API 正文

每个可独立使用的主要 API 至少有一个最小示例；同类函数、类族或共享生命周期允许共同示例，需明确覆盖成员。代码标注语言，示例前写明 `workspace`、`browser` 或 `npm`。包含必要容器、数据、样式、注册和清理，不依赖官网自动注入。

| API | 必须说明 |
| --- | --- |
| 原生组件 | 入口、构造/初始化签名、目标元素要求、选项、静态/实例成员、事件、更新、销毁 |
| Preact | 真实导入入口、Props、children、回调、受控/非受控行为、可用 ref、JSX 前提 |
| 自定义元素 | 标签、入口、注册、attribute/property 映射、类型转换、反射、只读属性、方法、事件 detail/触发时机/取消、slot、就绪/移除和表单语义 |
| 函数 | 签名与重载、参数、返回、异常、异步与取消、输入修改、单位/时区/空值边界、环境 |
| 类/状态对象 | 构造、静态/实例成员、状态所有权、订阅、持久化及资源清理 |
| 类型 | 完整定义或字段表、使用位置、泛型约束和关键联合分支 |

参数表使用：

```markdown
| 参数 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
```

无默认值写 `无`；动态默认值说明条件。不要将宽泛 `Function`、`Object` 作为终点，给出回调签名或对象类型。Markdown 表格中的联合类型 `|` 应转义。方法必须说明返回值，事件必须说明载荷与时机。继承成员不可静默省略。

## CSS 类与变量

每个 CSS 条目的元信息增加一个 `role`：

| role | 含义 | 正文要求 |
| --- | --- | --- |
| `component` | 可独立使用的 CSS 组件 | DOM 结构、基础类、必要子元素 |
| `js-component` | 配合 JS 组件的根类或部件类 | 所属组件、节点、是否由 JS 生成/维护 |
| `utility` | 可独立使用的工具类 | 作用、值集合、组合限制 |
| `helper` | 配合组件的辅助类 | 必需基础类、节点、父子关系、状态/尺寸等条件 |

“独立”不代表不依赖基础样式或主题。一个选择器有不同上下文角色时，分别列条目并说明匹配条件。内部实现类不列为推荐 API；解释内部结构时明确边界，特别是由 JS 管理的状态。

类族可合并，但列明实际支持的名称或模板和有界取值集合，不用 `p-*`、`hover:*` 暗示任意组合存在。CSS 源码的 `@apply -xxx` 不能直接当作公开类；按 [utilities 规范](utilities.md) 沿导入链核实。跨库提供的状态和皮肤应标明依赖。

变量表使用：

```markdown
| 变量 | 默认表达式 | 含义及取值 | 声明位置 | 推荐覆盖节点 |
| --- | --- | --- | --- | --- |
```

保留 `var(...)` 默认表达式，说明主题/状态影响和继承。组件节点上的声明可能覆盖祖先值，不将所有变量一律建议放到 `:root`。同族变量可以归组，正文列全实际变量和默认值。

## AI 编写与维护

1. 从 package.json、公共入口和再导出关系确认 API 清单。`zui.contributes` 只提示大类，不证明存在某个 API。
2. 从类型、实现、样式、测试和现有文档核实行为；默认值、注册、副作用和错误以运行时为准。
3. 按消费环境核实接入。遵循 [consumption](consumption.md)：`@zui/*` 是工作区入口，不据此承诺 npm；内部用 Preact 不代表公开 JSX；`/react` 不代表 React；源码存在、公开、注册、默认启用分别核实。
4. 按上述形态编写，不为套模板发明不存在的入口或 API。无法静态核实的行为执行最小必要验证；未执行的验证如实说明。
5. 修改公开入口、参数、事件、样式契约和注册方式时，同步更新相应条目并重新生成索引；纯内部变动无需机械改文档。

共享基础 API 只维护一处，其他库链接并写差异。公开能力清单应逐项核对；文件存在和格式通过不等于语义完整。没有可验证证据时不要为了通过检查删除“待核实”而改成肯定断言。

## 全局索引

生成器复用 `getLibs('buildIn', {root, cache: false})`，不加载本机 exts，不消费已筛选的官网侧边栏。包含所有发现的库；顶层 package.json.wip 被排除并单列报告，`zui.wip`、`zui.separately`、`zui.notReady` 保留并分别标记，不能合并成稳定性承诺。

按 `LibType` 既有顺序、再按库名稳定排序。根文件包含消费环境/检索提示、每库摘要/关键词/状态，以及组件和主要能力条目的锚点链接，不复制参数表和示例。摘要和条目数据取自库文档，包元数据取自 package.json。

相同输入生成相同字节，不含当前时间、本机路径，不调用 LLM。缺失文档明确报告，不写死链接。已有文档格式错误时生成失败并保留旧索引。生成文件标记禁止手改。

## 命令与验收

```sh
pnpm ai:build
pnpm ai:check
pnpm ai:export
pnpm ai:check-exports
pnpm ai:read --lib menu
pnpm ai:read --lib menu --section vanilla
pnpm ai:read --lib menu --section vanilla --entry vanilla-menu
```

`ai:build` 生成根 ai.md；`ai:check` 只读检查缺失文档、格式、未完成标记、本地链接及索引同步；`ai:read` 输出所选范围的 Markdown。指定 entry 必须同时指定 section，不存在的库/章节/条目和未知参数返回非零退出码。命令不联网、不执行示例。

校验分两层：脚本验证结构、链接和确定性；作者核对公开 API 覆盖和语义，针对新增消费方式验证示例。不得把结构检查写成所有示例的浏览器验收。脚本变更运行对应单元测试、lint、typecheck；文档变更运行 ai:build、ai:check，并按[共享流程](workflow.md#ai-参考联动)导出和检查应用侧参考。`pnpm check` 包含 ai:check 和 ai:check-exports；只读任务不生成文件。
