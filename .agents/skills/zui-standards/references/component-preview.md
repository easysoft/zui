# ZUI 组件预览规范

组件预览是每个可视组件库的标准资源，用于文档封面和组件展示墙，让用户在 **120 × 120** 的尺寸下一眼理解组件的主要外观、用途和配色。它是静态 HTML 示意图，交互行为仍由正式文档示例和开发调试页展示。

## 适用范围与交付

- 所有提供可视 UI 的内置 `lib/<name>` 都应有预览，包括 CSS 控件、复合组件、vanilla/Preact 组件、Web Component 和第三方 UI 封装；按实际用途判断，不仅按 `zui.type` 判断。纯 helper、store、配置或样式基础设施库没有独立可视组件时不强制提供。
- 新建可视组件库必须同时提供 `lib/<name>/assets/preview.html`。维护现有组件库时检查该文件，补齐目标库缺失的预览；主要外观、用途或典型状态变化时同步更新，已有预览仍准确时直接复用。
- 一个库保留一份代表性预览，选择最能体现核心用途的状态或少量主要变体，不按每个导出、主题或状态另建一份。
- 仅文案、翻译或用户明确限定文件范围的任务不自动扩展为补图；仅审计、评审时记录范围内的缺口并保持只读。不因单库任务顺带补齐其他库。

## HTML 与样式

- 文件是一份可直接插入容器的 HTML 片段，使用单个根节点。根节点采用 `w-full aspect-square`，由宿主设置宽度；以 120 × 120 为验收基准，保留足够内边距，不溢出、不滚动。
- 使用原生 `div`、`span` 等非交互元素，根节点设置 `role="img"` 和描述外观、用途或状态的 `aria-label`。内部没有可聚焦控件、链接或固定 ID，同一片段可以在页面中重复出现。
- 仅依赖宿主加载的 ZUI CSS。优先组合现有公开工具类，允许复用对应组件的公开样式（例如 `progress-striped`）；按 [CSS utilities 核实流程](utilities.md) 确认选择器、组合条件和实际 CSS 产物，组件专用 CSS 依赖须随预览接入说明。不能照搬未公开的 Tailwind 任意值或变体。
- 不包含脚本、事件属性、组件初始化属性、Web Component 标签、`iframe` 或网络请求；不依赖 `dev.ts`、ZUI JavaScript 或文档站运行时。无需 `html`、`head`、`body`、`link` 或 `style` 标签。
- 不使用 SVG、图片、Canvas、图标字体或截图。图形由圆角、边框、定位、旋转等已有 CSS 类表达；不要为封面新增全局样式或静态内联 CSS。
- 保持静态：无动画、闪烁或 hover 才出现的关键内容。条纹等状态可使用现成 CSS，但不添加动画类。

## 视觉约定

- 画面内没有可见文字和数字。用短线、圆点、网格或色块作为内容骨架，减少到足以识别用途的元素；名称和文档链接放在宿主的封面外部。无障碍描述不受无文字限制。
- 优先表现组件的特征结构与典型状态，如树形层级、分页当前项、展开的下拉菜单、选中日期或任务列，不把真实页面等比缩小后塞进封面。
- 与现有预览保持相同密度、圆角和留白。通用占位图标用圆形；搜索、上传、方向和状态等有辨识作用的图标保留必要几何形状。模态遮罩铺满整个封面背景，内容窗口居中。
- 使用 `bg-canvas`、`bg-surface-light`、`bg-gray-*`、`border-strong` 等主题类表达背景、骨架和边界，使用 `bg-primary`、`bg-success` 等表达主要状态。白色仅用于实色背景上的标记，不硬编码浅色或深色调色板。
- 同一份片段继承宿主主题：祖先 `dark` 启用深色，`light-in-dark` 恢复浅色，`dark-auto` 可跟随系统。两种模式都应保留组件轮廓、状态和内容层次，不增加预览专用主题脚本。

典型组件可采用以下构图；库内已有预览时先复用其风格与用法：

- 按钮：圆形图标、主次操作与骨架。
- 对话框：铺满背景的遮罩与居中内容。
- 进度条：普通与静态条纹状态。
- 看板：在小尺寸中保留列和卡片结构。

## 文档同步与展示

- [文档同步流程](../../../../scripts/docs/sync.ts)将库内 `assets/preview.html` 同步到 `docs/_/public/assets/<name>/preview.html`。源文件始终维护在库内，不手工编辑 `docs/_`。
- 新增预览时，在组件封面页源文件 `docs/docs/lib/previews.md` 添加入口；该页面不存在时按下述方式创建。名称与文档链接使用目标库的真实信息，修改片段时复用已有入口。
- 官网通过 VitePress 构建期 include 复用片段，在固定为 120 × 120 的 `vp-raw` 容器中展示。`@/` 在此语法中指同步后的文档根目录：

```md
<!--@include: @/public/assets/button/preview.html-->
```

- 展示墙或其他宿主也直接嵌入同一片段，并提供所需 ZUI CSS。HTML 资源不能当作 `<img src>` 使用；不为加载封面增加客户端脚本，也不复制片段形成第二份实现。
- 预览是文档资源，不因此新增运行时导出、包 `contributes` 或 npm 分发承诺。正式文档中的可运行示例仍遵循[文档规范](documentation.md)，不受静态封面的无脚本约束。

## 验证与交付

1. 检查目标库的预览文件、无障碍描述及展示页入口；核对没有可见文本、数字、脚本、初始化属性、媒体资源、可聚焦控件或固定 ID。
2. 核实所有 CSS 类已进入宿主使用的实际产物，不能只凭开发环境自动生成样式判定可用。新增或变更组件专用样式依赖时，确认其入口和消费说明。
3. 用现有同步流程更新目标资源及展示页，检查同步内容与源文件一致、include 能解析、文档链接正确；服务及生成物遵循[共享工作流](workflow.md)和仓库 `AGENTS.md`。
4. 在浏览器中检查 120 × 120 的浅色和深色效果：无溢出、裁切或滚动，轮廓和主要状态可辨认。另在只加载所需 CSS、禁用或阻止脚本的静态宿主中确认独立显示；文档站本身使用 JavaScript 不代表封面依赖 JavaScript。
5. 按本次变更运行必要检查，区分静态校验、同步和视觉验收；纯预览改动不自动要求全库构建或新增测试框架。汇报预览路径、可查看的页面和已验证状态。
