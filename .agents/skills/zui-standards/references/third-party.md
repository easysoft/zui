# 第三方依赖的版权与文档

组件、helper、整库开发或外部库封装引入新的第三方依赖时，版权文件和依赖说明属于本次交付的必要联动；替换或升级依赖时也要核对受影响的版本与授权。此要求覆盖 npm 包、运行时按需加载或 CDN 资源，以及复制、改编的第三方源码、CSS、字体和图标。

1. 按实际源码导入、加载路径及资源来源区分运行时依赖、复用源码/资源和纯开发依赖；同时检查本次新增且实际用于运行时的间接依赖。不能仅凭 `dependencies` / `devDependencies` 字段判断，随库提供并按需加载的脚本仍属于运行时依赖。
2. 在仓库根 `licenses/` 保存所用版本的完整上游版权、许可证及适用的 `NOTICE`，记录来源、版本和覆盖范围。已有文件只有在版权和条款确实覆盖本次使用时才可复用；同一上游多个包共用文件时注明覆盖包名。保留原始署名、许可条款及资源自带声明；不能只写许可证名称、链接或套用通用模板。
3. 运行时依赖和复用源码/资源同步更新 `docs/docs/guide/start/compatibility.md` 的“用到的第三方库”摘要，以及 `docs/docs/guide/about/dependencies.md` 的对应详细清单；详细清单说明项目/包名、用途、使用方式、授权协议及版权文件链接。组件所需的额外资源部署或加载步骤还应写入其正式文档。
4. 纯开发、构建、测试和文档站依赖更新 `docs/docs/guide/about/dependencies.md` 的开发依赖部分，保留该部分及未受影响条目，不混入兼容性页的运行时清单；同样按第 2 项核对版权文件。
5. 交付前对照本次依赖与资源变化，检查版权原文、版本/包覆盖和文档链接，并确认两处运行时清单一致。来源或授权无法核实时记录缺口并报告，不能用来源说明代替缺失的许可证或宣称已核实。

只读任务只核对并报告；用户明确限制文件范围时遵循其限制并说明未完成项。既有依赖未受本次变更影响时，不顺带扩大为全仓库版权审计。
