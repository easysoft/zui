# ZUI 国际化规范

## 当前基础设施

`@zui/core` 提供 `i18n`：

- 全局语言默认读取 `<html lang>`，缺省为 `zh_cn`；
- 语言码会转为小写并将 `-` 归一化为 `_`；
- `i18n.addLang()` 合并全局语言映射；
- Component/HElement 可从静态 `i18n`、实例 options/props `i18n` 和 `lang` 获取私有翻译；
- `ComponentFromReact` 会合并视图组件的 i18n 数据。

实现前阅读 `lib/core/src/i18n/`、目标消费组件和两个相似库，不根据历史示例猜测 API。

## 语言文件

默认提供：

- `zh_cn`
- `zh_tw`
- `en`

先定义基础对象，再约束其他语言键结构：

```ts
const zh_cn = {
    empty: '暂无数据',
    total: '共 {0} 项',
};

const zh_tw: typeof zh_cn = {
    empty: '暫無資料',
    total: '共 {0} 項',
};

const en: typeof zh_cn = {
    empty: 'No data',
    total: '{0} items',
};
```

使用 `typeof zh_cn` 或等价的 `satisfies`/共享类型，保证键和嵌套结构一致。翻译对象保持数据化，不在其中执行浏览器副作用。

## 私有映射与全局命名空间

组件私有 UI 文案优先挂在组件静态 `i18n` 映射上，使 options/props 中的 `lang` 和 `i18n` 覆盖能够工作。Preact + vanilla 组合要确认 `ComponentFromReact` 的映射合并路径真实可达。

跨组件共享或 helper 提供的通用翻译使用全局映射，并加稳定命名空间：

```ts
i18n.addLang({
    zh_cn: {example: zh_cn},
    zh_tw: {example: zh_tw},
    en: {example: en},
});
```

不要把组件私有键无前缀写入全局空间，避免覆盖其他库。

## 加载与消费

- 从 `src/i18n/index.ts` 或当前库既有位置导出/注册。
- 确保 `src/main.ts`、组件 share 入口或实际消费路径导入语言文件；只创建未导入文件不算完成。
- 已继承 core 的基础 options 时，不重复声明 `lang`/`i18n`，除非公共类型确实没有这些字段。
- 用户可见字符串通过 i18n 获取；开发日志、内部错误标识和协议值不必翻译。
- 占位符使用 `{0}`、`{1}` 或 `{name}`，各语言保留同一组占位符。

## 回退与覆盖

明确并验证：

- 组件 options/props 的 `lang` 是否覆盖全局语言；
- options/props `i18n` 是否覆盖静态映射；
- 缺失键是否使用默认值或全局/静态下一层；
- 不支持的语言码如何处理；
- `zh-CN` 等输入是否正确归一化；
- 动态切换语言是否需要重新 render。

不要承诺源码没有实现的自动回退链。当前 `i18n` 按给定语言或 `default` 取值；需要额外 fallback 时必须作为 API 设计明确提出。

## 验证

- 静态比较三种语言的键和嵌套结构。
- 对每种语言执行至少一个真实消费路径。
- 测试全局语言、组件语言覆盖、实例映射覆盖、占位符和缺失键默认值。
- 检查语言文件可从发布入口加载。
- 运行类型检查和目标库构建；若有调试页，在同页展示或切换三种语言。
