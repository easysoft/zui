# ZUI 源码与文档接入规范

新增或修改跨库导入、公开入口、类型导出、安装说明及可复制示例时，按本规范核实所承诺的消费方式。库结构与依赖分类沿用 [库规范](library.md)，官网示例结构沿用 [文档规范](documentation.md)。

## 按使用环境选择入口

| 使用环境 | 入口约定 | 核实依据 |
| --- | --- | --- |
| ZUI 源码工作区 | `@zui/<name>` 及该库真实公开的子路径 | `lib/<name>/package.json`、目标入口与源码、工作区解析配置 |
| 浏览器与官网普通 JS 示例 | 已加载的全局 `zui.Member` | 目标版本的实际 JS/CSS 产物及构建包含的库 |
| 标准 npm 包消费 | 从 `zui` 导入成员，通过 `zui/css` 引入样式 | 目标 npm 包的 `exports`、运行时成员及声明文件 |

当前标准 npm 包只声明 `zui` 和 `zui/css` 两个入口。当前源码的分发契约从 `publish/package.json`、`scripts/build/package.ts` 和 `scripts/build/npm-types.ts` 核实；已发布版本以该版本的实际包为准。根目录的开发清单、Vite 别名或工作区软链不能证明 npm 包提供同样的路径。

`@zui/*` 是本项目的工作区包命名；目录存在、工作区能解析或源码有导出，均不能作为独立 npm 发布的证据。不得由库名推导 `zui/<name>`、`zui/<name>/react` 或其他未声明的入口。

## 源码约束

- 跨库复用通过目标库公开的 `@zui/<name>` 入口或已声明子路径；不要在 `lib/*/src` 中反向依赖聚合发布包 `zui`，也不要通过相对路径、`@zui/<name>/src/*` 或仓库别名绕过库边界。同库内部可以使用相对路径。
- 导入前核实路径可解析、成员确实导出且形态匹配。新增入口时同步维护所需包元数据、入口文件和依赖；不要为套用文档模板而补出组件并不具备的 `/css`、`/react`、插件或 Web Component 入口。
- Preact 组件、vanilla 构造器、Web Component 定义分别核实。库采用 Preact 实现不代表每种形态都对外公开；只有 vanilla API 的库不承诺 JSX 用法。
- 仅用作类型的导入使用 `import type`。工作区类型与聚合 npm 类型分别核实，尤其是重名类型的别名；维护 npm 聚合别名时保留已有工作区 API，不能把类型声明当作可实例化的运行时成员。
- 改变分发入口或公开类型时，检查最终运行时和声明是否一致。发布包的声明不能要求消费者解析仓库内的 `@zui/*`、本机绝对路径或构建临时目录；复用现有声明生成和 npm 消费测试。
- 公开入口、类型或组件形态变化时，同步核对受影响的正式文档与可复制示例，在任务范围内修正接入说明；任务明确限制为源码时，报告待联动的文档差异。

## 文档约束

- 新建或重构普通组件页时，先给出按公共接入指引即可运行的 HTML/JS 基础示例，普通 JS 通过 `zui` 访问成员。不要让源码工作区配置成为普通使用的隐含前提；纯 CSS 或仅提供源码 API 的库按其真实形态说明。
- npm、源码工作区和 Preact 用法按实际需要分节，标题与代码前的说明须明确环境。只有 ESM 语法并不足以说明包从何处取得；不要把 `@zui/*` 放在“通过 npm”或“ESM/npm”章节中当作标准包用法。
- 源码示例在第一段相关代码前说明工作区前提，例如：“以下示例用于 ZUI 源码工作区，需要解析 `@zui/*` 并编译 TypeScript；使用 JSX 时还需配置 Preact。”同一节无需重复。额外的样式入口、独立资源、插件注册和副作用导入按真实需要补充。
- 历史命名 `/react` 不代表 React 支持；核实该库的 `exports` 和对应实现后，才可展示 Preact 用法。使用 Preact 的 `render(vnode, container)` 和实际 JSX 配置；不得把 vanilla 类作为 JSX 组件，或照抄其他库的 `/react` 路径。
- TypeScript 代码也属于接入示例：标准 npm 示例使用实际发布的类型名与入口；仅从工作区导出的类型留在明确标注的源码章节。不要把所有 `@zui/*` 机械替换成 `zui`。
- 独立 helper、插件和子模块需核实标准包是否导出、是否已注册，以及是否依赖 DOM。源码模块可在 Node 中运行，不代表聚合 `zui` 入口也可在无 DOM 环境运行。
- 可复制代码应包含所需容器、示例数据及初始化，并与预览行为一致。安装步骤引用公共指引；`<Example>`、`<ZUI>`、文档站自动注入的变量或样式不属于用户代码的隐含依赖。公开 CSS 类继续按 [utilities 规范](utilities.md) 核实。

## 范围与版本

接入说明修复保留既定目标版本，不顺带升降 npm/CDN 版本或改变构建筛选、发布配置。只有本次任务本就包含版本或发布契约调整时才修改相应内容。

发现目标版本尚未发布、资源不可用，或已发布包与当前源码能力不同，单独报告事实与验证限制。需要验证当前源码时可使用对应候选包，但要说明候选包来源，不能把其他版本或本地构建通过写成目标已发布版本验证通过，也不为完成文档修复自动发布。

## 按变更验证

按本次改变的消费方式选择检查，不因纯文案调整构建整库：

| 变更 | 必要验证 |
| --- | --- |
| 只调整环境标签或说明 | 对照真实包入口和源码，检查相邻代码与说明是否一致 |
| 新增或修改 npm 导入、类型或可复制代码 | 在不继承仓库别名和工作区链接的独立消费项目中，使用匹配目标的包验证原样代码；涉及类型时编译检查，涉及 UI 时在浏览器验证初始化及所需样式 |
| 新增或修改源码工作区、Preact 或插件示例 | 在说明的工作区配置中检查解析、类型及对应渲染或注册行为 |
| 改变源码公开入口、依赖或分发类型 | 运行受影响的 lint、类型和既有测试，按契约补充目标构建、npm 消费或分发测试；新增回归优先扩展现有相关测试 |
| 改变官网示例结构、资源或生命周期 | 按文档规范选择同步、文档构建或浏览器检查，覆盖受影响的初始化与清理 |

npm 包消费优先复用 `tests/build/npm-consumer.test.ts`；浏览器分发按需复用 `tests/build/distribution.test.ts`。实际命令、候选包生成与隔离规则遵循仓库 `AGENTS.md` 和 [共享工作流](workflow.md)，不修改生成产物代替修复源文件。

文档构建只验证站点能否生成，不能证明 Markdown 代码块能在用户项目中运行。交付时分别说明核对的目标版本/包来源、静态或类型检查、构建及实际运行结果；未完成的环节明确列出。
