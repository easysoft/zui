# 第三方依赖的版权与文档

组件、helper、整库开发或外部库封装引入新的第三方依赖时，版权文件和依赖说明属于本次交付的必要联动；替换或升级时核对受影响的版本与授权。此要求覆盖 npm 包、按需加载或 CDN 资源、复制或改编的源码/CSS/字体/图标，以及本次新增且实际用于运行时的间接依赖；按实际使用方式分类，不能仅凭 `devDependencies` 排除随库加载的资源。

1. 在 `EXT_ROOT` 的既有版权目录保存所用版本的完整上游版权、许可证及适用的 `NOTICE`；未约定目录时使用 `EXT_ROOT/licenses/`。记录来源、版本和覆盖包/资源，保留原始署名、条款及资源自带声明；复用已有文件前确认覆盖当前使用，不能只写许可名称或链接。
2. 更新 `EXT_ROOT` 内既有的第三方依赖说明，记录项目/包名、用途、使用方式、授权协议及版权文件链接；存在兼容性页时，同步其运行时依赖清单。没有对应说明时，在扩展项目 README 中增加第三方依赖部分。组件额外资源部署或加载步骤写入其正式文档。
3. 开发、构建、测试及文档站依赖保留在开发依赖部分，不混入运行时清单；同样核对版权文件。遵循扩展项目实际文档布局，不把宿主 `docs/docs/...` 路径直接套入扩展项目，也不为登记扩展依赖修改宿主版权或文档。
4. 交付前对照本次依赖和资源变化核对版权原文、版本/包覆盖及文档链接。来源或授权无法核实时记录缺口并报告，不能以来源说明替代许可证或宣称已核实。

只读任务只核对并报告；用户明确限定文件范围时遵循其限制并说明未完成项。上述联动仅在 `EXT_ROOT` 内，不扩大宿主写权限，也不因局部依赖变化审计无关依赖。
