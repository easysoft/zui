# ZUI 扩展库国际化规范

## 读取当前基础设施

新增接线或改变覆盖/回退行为时，核实当前宿主相关 i18n、组件基类或 `ComponentFromReact` 契约，并阅读目标消费路径及必要参考。局部文案修订核对涉及的键、占位符与语义；阅读范围遵循 [共享工作流](workflow.md)，不套用另一项目的历史模板。

本次涉及语言接线、覆盖或回退时，确认当前实现如何处理全局语言、语言码归一化、`i18n.addLang()`、静态组件映射、实例 `lang` / `i18n` 覆盖和 default/fallback。

## 语言与键结构

- 默认语言集合优先服从 `EXT_ROOT` 现有约定；若没有约定，ZUI 常用集合是 `zh_cn`、`zh_tw`、`en`。
- 用基础语言对象的 `typeof`、`satisfies` 或共享类型约束其他语言键、嵌套和占位符一致。
- 只翻译用户可见文本；协议值、CSS 类、事件名、字段 key 和内部错误标识保持稳定。
- 占位符使用宿主当前支持的形式，并在所有语言保留同一集合。

## 私有映射与全局命名空间

组件私有文案优先使用组件静态映射，以便实例语言和 i18n override 生效。跨组件/helper 共享文案才使用全局注册。

全局命名空间必须在全部已发现内置库和扩展库之间稳定且唯一。基于真实 `PACKAGE_NAME`、既有扩展约定和公开兼容性设计，不机械把 `LIB_FOLDER` 转 camelCase，也不固定使用某一品牌 scope。

沿用目标库现有模式时，先验证它确实支持 override、fallback 和动态切换；发现局部历史惯例与当前宿主冲突时报告并按批准范围处理。

## 加载与覆盖

- 确保语言文件从真实 package 入口或组件消费入口可达；只创建未导入文件不算完成。
- 不重复声明基类已提供的 language options。
- 明确全局语言、实例 `lang`、实例映射、缺失键默认值、不支持语言和动态切换的优先级。
- 不承诺当前宿主未实现的 fallback 链。

## 验证

按共享工作流选择本次所需检查；新增语言或改变对应行为时覆盖相关项目：

- 程序化比较所有语言键、嵌套和占位符。
- 扫描目标范围用户可见硬编码，但区分注释、fallback、协议值与开发日志。
- 对每种语言执行真实消费路径，覆盖实例 override、缺失键和动态变化。
- 在 `EXT_ROOT` 运行受影响的现有检查；改变语言加载与分发时补充所需宿主构建，改变切换行为时补充对应调试。
