# ZUI 文档站

<!-- impeccable:product-schema 1 -->

## Platform

web

## Scope

本文件记录 `docs/` 文档站的产品上下文，用于指导该站点后续的设计与内容工作。ZUI 是一个前端开发框架；文档站面向使用 ZUI 进行项目开发的用户。

## Users

主要用户是将 ZUI 用于实际项目开发的开发者，包括首次接入 ZUI 的用户，以及开发过程中反复查阅组件、工具类和 API 的用户。

用户来到文档站，是为了理解如何使用 ZUI、找到适合当前任务的能力，并将示例应用到自己的项目。源码贡献、框架内部实现和仓库维护资料作为补充内容，不能成为学习日常用法的前置条件。

## Product Purpose

帮助用户从了解 ZUI、完成接入，到组合组件与工具类、配置交互、定制主题，持续完成项目开发任务。

文档有效的判断依据是：用户能够找到相关说明，理解适用条件，运行示例，并依据准确的 API 和限制说明完成自己的实现。尚未设定量化的产品指标。

## Positioning

ZUI 是可组合、可定制的前端开发框架，提供基础样式、CSS 工具类、CSS 组件和 JavaScript 组件。使用 ZUI 不要求应用采用特定 JavaScript 框架；它支持原生 DOM 调用、浏览器脚本、ES Module 和定制构建等接入方式。

文档站围绕这些公开能力提供上手指引、可交互示例、示例代码、API 参考及定制说明，帮助用户把同一套框架用于自己的技术栈与业务场景。

## Operating Context

- 初次使用：阅读介绍与快速上手，选择接入方式，在自己的页面中运行第一个示例。
- 日常开发：通过导航或本地搜索定位工具类、组件和 JS 工具，查看运行效果、代码、选项、事件与方法。
- 深入使用：查阅主题配置、定制构建、扩展与兼容性说明，处理项目中的具体约束。
- 当前文档主要使用中文，代码标识符与公开 API 保持一致。

文档站使用 VitePress 与 Vue。站点的实现技术不构成 ZUI 使用者的技术栈要求；ZUI 组件内部使用的 Preact 和 Cash 也不应成为普通接入教程的前置知识。

## Capabilities and Constraints

- 保留 ZUI 的框架无关接入、按需组合、主题定制及深色模式能力，示例须说明所需资源与初始化条件。
- JavaScript 组件依赖浏览器 DOM；SSR 项目须在客户端加载并初始化相关组件。不能将浏览器脚本示例描述为可直接在服务端执行。
- 说明以公开类型、源码默认值及实际分发行为为依据。示例中的资源、数据、HTML 与初始化代码应足以支撑所演示的功能。
- 浏览器兼容性以 `docs/guide/start/compatibility.md` 为准；编译目标、自动化测试覆盖和真实设备验证是不同层次的证据。
- 通用指南源位于 `docs/`；各库文档源位于仓库的 `../lib/<name>/docs/`。`_/.vitepress/` 中受版本管理的配置与主题是源码，`_/` 中同步生成的页面和构建产物不作为编辑源。
- 从仓库根目录运行 `pnpm docs:dev` 准备并启动文档站，默认端口为 5174；构建与官网示例验收分别使用 `pnpm docs:build` 和 `pnpm test:docs`。具体维护流程以 `README.md` 和仓库 `../AGENTS.md` 为准。
- 本文件位于文档项目根目录，不属于面向读者发布的内容源目录。

## Brand Commitments

- 产品名称使用「ZUI」或明确版本语境下的「ZUI 3」；产品定位使用「前端开发框架」。
- 现有品牌图形源为仓库根目录的 `../favicon.svg`，文档站将其用作 Logo 与站点图标。
- 公开 API、参数名、类名与资源名必须准确；内容不得暗示未经证实的能力、性能或兼容性承诺。

- `docs/index.md`：现有首页的产品介绍与功能文案。

这些资料证明已有内容和功能的存在，不等同于本次已完成构建、浏览器验收或无障碍认证。没有确认的用户证言、采用规模或性能数据不得补写为产品事实。

## Product Principles

1. **围绕项目开发任务组织说明。** 先帮助用户理解如何使用，再按需要展开内部机制与贡献流程。
2. **让示例能够落地。** 运行效果与示例代码对应，接入前提清楚，用户可以据此迁移到自己的项目。
3. **让查阅结果可信。** 文案、公开 API、默认行为与分发产物保持一致，限制与适用条件明确。
4. **尊重用户既有技术栈。** 准确呈现原生调用与不同接入方式，避免把文档站或框架内部的实现依赖变成消费方要求。

## Accessibility & Inclusion

仓库已有自动化可访问性检查，并明确要求对键盘顺序、焦点、屏幕阅读器、缩放和兼容性边界进行人工验证。后续文档站工作应保留语义结构和键盘操作能力，不能仅凭自动化扫描宣称全面合规。

尚未确认文档站专属的无障碍合规等级、主要读者熟练度，以及桌面与移动设备的优先级；具体设计任务需要这些条件时再补充。
